# Architecture

This document describes how the Zaštiti.me site is put together and the rules that keep it simple. Read it before your first change. It describes the target structure. Where the code doesn't match yet, the [Status](#status) section says so.

Format after matklad's [ARCHITECTURE.md](https://matklad.github.io/2021/02/06/ARCHITECTURE.md.html): a bird's-eye view, a code map, invariants, then cross-cutting concerns. It stays short on purpose: anything you can learn from one file belongs in that file.

## Bird's-eye view

Zaštiti.me is a small, bilingual (Montenegrin first, English second), mostly static information site for an NGO fighting digital violence against children. It has one job beyond showing pages: **accept SOS reports and contact messages and deliver them safely to the team.**

There is **no CMS and no database**. All content lives in this repository as JSON and TypeScript. A content change is a code change: edit a file, open a PR, deploy. Changes come in from the client a few times a month, so editing safety (types, review, preview deploys) matters more than editing convenience.

```
request ─▶ proxy.ts (locale redirect) ─▶ app/[locale]/… (static HTML, built at deploy)
                                                │
                                                ├─ reads content/ (messages + collections) at build time
                                                └─ SOS / contact form ─▶ Server Action ─▶ email (+ ticket)
```

Stack: Next.js 16 (App Router, Cache Components, React Compiler), React 19, Astryx (`@astryxdesign/core`) with our `zastiti` theme, Phosphor icons. No Tailwind and no shadcn.

## Code map

```
app/
  [locale]/                  every page lives under the locale segment (me | en)
    layout.tsx               root layout: generateStaticParams (me, en), <html lang>, fonts, Providers, header, footer
    page.tsx                 home: the two doors (kids, parents)
    dictionaries.ts          getLocale() / getDictionary(): locale from next/root-params, typed messages
    sos/                     report form page + actions.ts (Server Action)
    kontakt/                 contact form page + actions.ts
    roditelji/ djeca/ digitalno-nasilje/ o-nama/ aktivnosti/ biblioteka/ …
    aktivnosti/[slug]/       detail pages: generateStaticParams from content/, notFound() for unknown slugs
  global-not-found.tsx       the one 404 page, bilingual (see "Not found" below)
  providers.tsx              client boundary: Astryx <Theme> + <LinkProvider component={Link}>
  globals.css                cascade-layer order + body paint. Nothing else.
components/                  site components composed from Astryx (PathCard, SiteHeader, SiteFooter, ReportForm…)
content/
  messages/me.json, en.json  every UI string and page copy, keyed identically
  <collection>.ts            structured lists (activities, guides, library, team): typed arrays, both locales
lib/
  i18n.ts                    locales, defaultLocale, htmlLang, hasLocale(). Plain constants, safe in proxy and client code.
  email.ts                   server-only: sends mail through the provider
  reports.ts                 server-only: validates, escapes and formats SOS/contact payloads
src/
  astryx-themes.ts           GENERATED by `astryx theme add`. Don't edit.
  themes/zastiti/            our Astryx theme: zastitiTheme.ts (source), icons.tsx (Phosphor registry), generated build outputs (gitignored)
proxy.ts                     redirects `/` and unprefixed paths to /me, always. No browser-language detection.
public/                      static files: logo, images (images/<collection>/…), favicon
old-site-reference/          gitignored copy of the previous site. Source of approved copy only. Never import from it.
```

`src/` exists only because the Astryx CLI insists on `src/themes/` and `src/astryx-themes.ts`. Everything else stays at the root.

## Invariants

These are the rules the code relies on. Breaking one needs a discussion and an update to this file.

1. **Every page is static.** Pages render at build time from `content/`. No request-time data fetching and no `fetch` to external content APIs. The only dynamic code is form Server Actions. If a page shows up as dynamic in `next build` output, that's a bug.
2. **Content lives in `content/`, never in components.** Components take content as props or read it through `getDictionary()`. A string hard-coded in JSX is a bug, unless it is a brand name.
3. **Both locales always have the same keys.** `Messages` is `typeof me.json`, and `en.json` must satisfy it, so a key missing from English fails `tsc`. An *extra* English key doesn't fail, so delete keys from both files together. Collections type every user-facing field as `{me: string; en: string}`.
4. **Approved copy is used verbatim.** Copy from `old-site-reference/zastiti-me/messages/*.json` is approved by the client. Moving it is fine. Rewording it needs the client's OK. Sentence-casing title-cased headings is the one allowed edit (see the design system).
5. **URLs stay compatible with the live site.** `/me/…` and `/en/…` with the existing Montenegrin slugs (`/sos`, `/roditelji`, `/djeca/video-vodici`, …). Removing or renaming a route needs a redirect in `next.config.ts`.
6. **Report data never touches the browser's network tab beyond our own origin.** Forms post to Server Actions. Recipients, API keys and the email HTML are built server-side from env vars. No `NEXT_PUBLIC_*` secret, no client-side calls to email or ticket APIs. (The old site did all three. Don't port that code.)
7. **User input is escaped and bounded.** Validate every form with a schema. Cap text length and attachment count, size and type. HTML-escape everything that goes into an email. Never log report contents.
8. **Styling goes through the theme.** Astryx components and props first, then Astryx tokens (`var(--color-*)`, `var(--spacing-*)`). No raw hex or px in `app/` or `components/`, and no `:root` overrides. To change the look, edit `src/themes/zastiti/zastitiTheme.ts` and rebuild the themes (see How to… below).
9. **The generated files are never hand-edited.** `src/astryx-themes.ts` is written once by `astryx theme add`/`theme use` and is committed. The theme build outputs (`src/themes/zastiti*/zastiti*.{css,js,d.ts,css.d.ts,variants.d.ts}`, all four themes) are gitignored and never committed. `npm run themes` regenerates them, and it runs before `npm run dev` and `npm run build` (so Vercel builds them too). `tsc` and lint need them, because the `.variants.d.ts` files carry the custom variant types, so on a fresh clone run `npm run themes` (or `dev`/`build`) first.
10. **Server Components by default.** Add `'use client'` only to the smallest component that needs state, effects or event handlers (forms, quiz, accordion). Pages stay server components and pass plain data down.

## Cross-cutting concerns

### Content and translations

- **Messages** (`content/messages/*.json`) hold every short string and page copy, namespaced by page (`home.*`, `sos.*`, `parents.*`). Pages call `getDictionary()`, which reads the locale from `next/root-params` (see Next's internationalization guide in `node_modules/next/dist/docs/01-app/02-guides/internationalization.md`). No i18n library.
- **Collections** (`content/activities.ts`, `content/guides.ts`, …) are typed arrays sorted newest-first, each item with a stable `slug`, a `date`, and localized fields. Detail routes read the same array in `generateStaticParams` and call `notFound()` when a slug isn't in it. Cache Components rules out `dynamicParams = false`.
- **Client components never read the locale themselves.** `next/root-params` only works on the server, so pages pass localized strings down as props (see `components/HomeDoors.tsx`).

### Not found

`app/[locale]/layout.tsx` is the root layout, and a `not-found.tsx` inside `[locale]` renders a broken error shell (tested on Next 16.4.6). Instead, `experimental.globalNotFound` is on, and `app/global-not-found.tsx` serves every 404: unmatched URLs and `notFound()` calls alike. It bypasses the layout, so it loads its own fonts, CSS and providers. It can't know the locale, so it shows Montenegrin and English together with links to `/me` and `/en`.
- **Long-form articles:** keep bodies as short paragraphs in the collection. When an article needs real formatting (headings, lists, embedded images), add `@next/mdx` and store `content/<collection>/<slug>.<locale>.mdx`. Do it once, for all articles.
- **Images** go in `public/images/<collection>/<slug>.webp` and render through `next/image` with real `alt` text in both locales.

### Forms (SOS and contact)

- `app/[locale]/sos/actions.ts` is a Server Action. The form component is a client component using `useActionState` for pending, error and success states.
- Flow: validate (schema) → escape → build email server-side → send through `lib/email.ts` → optionally create a ticket → return `{ok}` or a field-error map. No toast libraries: show the result inline with Astryx components.
- Attachments: Server Actions cap request bodies at 1 MB by default. Raise `experimental.serverActions.bodySizeLimit` in `next.config.ts` to just above the agreed attachment limit, and also enforce that limit in the schema.
- Anonymous reports send no name, email or phone, even if the fields were filled before switching to anonymous.

### Accessibility

Target WCAG 2.2 AA. The design system already guarantees contrast and focus rings. Pages must keep one `h1`, labelled fields, error text tied to fields (`aria-describedby`), and a working keyboard path to the SOS form from every page.

### Testing and checks

Before every PR: `npm run lint`, `npx tsc --noEmit`, and `npm run build`. Check the build output: every route must be static (○), except routes that only host forms. Before merging layout changes, also check `npx astryx doctor`. Content-only PRs need a preview-deploy look in both locales.

## How to…

- **Change copy:** edit the key in `content/messages/me.json` *and* `en.json`. `tsc` fails if you only do one.
- **Add an activity, guide or book:** append an item to the collection in `content/`, add its image under `public/images/<collection>/`, then build. The detail page appears automatically.
- **Add a page:** create `app/[locale]/<montenegrin-slug>/page.tsx`, add its messages namespace to both JSON files, and link it from the header or footer config in `components/`.
- **Change a colour, radius or font:** change it in the design system first, mirror it in `src/themes/zastiti/zastitiTheme.ts`, then rebuild all four themes, since the audience themes extend it. While you work, keep `npx astryx theme build --watch src/themes/zastiti*/*Theme.ts` running, or run `npm run themes` once (`dev` and `build` also run it). The outputs are gitignored, so only the `*Theme.ts` source shows up in the diff.
- **Retire a page:** delete the route and add a permanent redirect in `next.config.ts`.
- **Upgrade Astryx:** after `npx astryx upgrade`, check that the header links (`data-site-nav-links` in `components/SiteHeader.tsx`) are still centred between the logo and the buttons at 1024px and 1440px. They are stretched by one rule in `app/globals.css`, because TopNav has no option for it; if TopNav's markup changes, the links slide back against the logo. Also open the mobile menu: it replaces Dialog's open animation and sizes its icons through `app/globals.css`, so check it still slides down and its two icons are 32px. On a desktop at 1024px or wider, hover a homepage door: the rise on hover is drawn in `app/globals.css` on ClickableCard's `data-variant` (only for devices that can hover), so check it still lifts 2px.

## Status

Built so far:
- the Astryx setup, the `zastiti` theme with Phosphor icons, fonts and providers
- locale routing: `[locale]` root segment, `proxy.ts`, `lib/i18n.ts` and typed dictionaries
- `content/messages/`, copied verbatim from `old-site-reference/`
- the home page with the two doors (kids, parents), in both languages
- the About page (`/o-nama`): rows built from the theme's inner-page Section variants (`row`, `split`, `split-reverse`, `split-hero`, `band-muted`, `band-brand`), whose two halves are `components/Split.tsx`. Split rows are 5:7 on desktop, equal halves on tablets (600-1023px) and stacked on phones, text first in the markup at every width. Its illustrations are jigsaw pieces pre-cut with transparent edges (`public/images/about/`). The team and partners (`content/team.ts`, `content/partners.ts`) are seed data until the client sends the real ones
- the bilingual global 404
- the header (`components/SiteHeader.tsx`, in AppShell's top nav, with a ME/EN link that keeps the current path); below 1024px its menu button opens `components/MobileMenu.tsx`, a paper sheet from the top (an Astryx `Dialog`; AppShell's own drawer is unused) and footer (`components/SiteFooter.tsx`); their links live in `components/siteNav.ts`
- audience colours: `components/AudienceTheme.tsx` wraps the header and page in a nested Astryx theme by URL (`/roditelji` teal, `/djeca` sun, `/sos` coral; shared pages keep brand green). The three themes in `src/themes/zastiti-{roditelji,djeca,sos}/` extend `zastiti` and swap only the accent family

Not built yet:
- `content/` collections other than the About page's team and partners
- every page except the home and About pages
- a remembered language choice (Montenegrin stays the default; the header switch only swaps the locale segment)
- the forms and `lib/`
- the logo as SVG (the header and footer use the old site's PNG, `public/images/logo.png`, through `components/Logo.tsx`)
- social links (the footer shows none until the client sends the real profile URLs)
- Montenegrin strings for Astryx's own labels ("Skip to content", "Open navigation"); they fall back to English

Open decisions:
- the email provider
- whether to keep the Starko ticketing and chat widget
- the hosting platform
- the attachment limits for the SOS form
- analytics (if any)
